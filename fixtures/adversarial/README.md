# Adversarial inputs

Hostile and malformed project files. Every one must be refused (or, for the
Trojan Source case, parsed with a warning) with a precise, stable error code
and never crash, hang, read a file, or make a network request.
`packages/core/test/l5x/adversarial.test.ts` runs each file through the real
ingest path (`decodeProjectBytes` → `parseProjectText`) and asserts the code.

All content is synthetic. The files are generated by `generate.ts` in this
directory (`node fixtures/adversarial/generate.ts`) because two of them need
exact bytes (invalid UTF-8, U+202E); regenerate rather than hand-edit them.

| File | What it is | Expected result |
|---|---|---|
| `xxe-external-entity.L5X` | A DOCTYPE declaring `<!ENTITY xxe SYSTEM "file:///etc/passwd">` and using `&xxe;` in a tag description. | `XML_DOCTYPE_FORBIDDEN` |
| `billion-laughs.L5X` | Classic entity-expansion bomb: ten nested levels of ten references each (10^9 copies of "lol"). | `XML_DOCTYPE_FORBIDDEN` |
| `xxe-parameter-entity.L5X` | A parameter entity `%remote;` pointing at an external DTD on an attacker host (blind XXE / out-of-band exfiltration). | `XML_DOCTYPE_FORBIDDEN` |
| `truncated.L5X` | A valid export cut off after a complete `<Tag>`: every open element is left unclosed (an interrupted copy or upload). | `XML_UNCLOSED_TAG` |
| `wrong-root.xml` | Its head mentions `<RSLogix5000Content` in a comment, so the L5X sniff picks it, but the real root is `<Project>`. Detection is a hint, not trust. | `L5X_WRONG_ROOT` |
| `mismatched-tags.L5X` | `<Description>` closed by a misspelled `</Descripton>`. | `XML_MISMATCHED_TAG` |
| `duplicate-attribute.L5X` | A `<Tag>` with `ExternalAccess` twice. Parsers disagree on which value wins, which can hide an HMI-writable safety tag. | `XML_DUPLICATE_ATTRIBUTE` |
| `unterminated-cdata.L5X` | The last CDATA section in the file (a rung's text) has no `]]>`. | `XML_UNTERMINATED_CDATA` |
| `invalid-utf8.L5X` | Bytes `C3 28 FF` inside a description: invalid UTF-8. Never decoded leniently into U+FFFD. | `ENCODING_INVALID` |
| `bidi-tag-name.L5X` | A tag description containing U+202E RIGHT-TO-LEFT OVERRIDE and U+202C POP DIRECTIONAL FORMATTING, so the text displays differently from what it contains (Trojan Source). | Parses; the characters are removed and a `TEXT_INVISIBLE_CHARACTERS` warning names the tag. |
| `not-xml.L5X` | Plain text with an `.L5X` extension. | `XML_NOT_XML` |
| `plcopen-sample.xml` | A tiny, valid-looking PLCopen TC6 XML project. | `FORMAT_NOT_SUPPORTED` (recognized and declined honestly) |
| `unknown-entity.L5X` | `&nbsp;` in a task's `Name` attribute: an entity that would need a DTD (inside CDATA it would just be text). | `XML_UNKNOWN_ENTITY` |
| `deep-nesting.L5X` | 5,000 nested elements inside `<Controller>`. Must fail on the depth limit, never with a stack overflow. | `XML_TOO_DEEP` |
| `missing-program-name.L5X` | A `<Program>` with no `Name` attribute: it cannot be identified, scheduled or referenced. | `L5X_MISSING_NAME` |
| `prototype-attributes.L5X` | A `<Tag>` with attributes named `__proto__` and `constructor`. They must stay inert data; no prototype is polluted. | Parses normally. |
